# 配信時の端末の発熱を調査する

- Branch: feature/debug-investigate-heat-generation
- Polished: {YYYY-MM-DD}

## 目的

Sora Unity SDK で配信した時の端末の温度上昇を、ハードウェアアクセラレータ (HWA) の有無やコーデックの違いごとに計測して記録する。発熱は長時間配信の安定性や利用者の端末負荷に直結するため、実測値をもとに SDK が推奨できる設定を判断できるようにする。

## 現状

- 現状の発熱に関する実測データはない。
- SDK は VP8 / VP9 / AV1 / H.264 / H.265 と、Apple VideoToolbox / NVIDIA VIDEO CODEC / Intel VPL / AMD AMF の HWA に対応している (AMD AMF は非推奨)。
- 解像度・フレームレート・ビットレート・HWA の有無を変えたときの端末温度は比較されていない。

## 調査方針

- 1080p / 60fps を基準に、VP8 / VP9 / AV1 / H.264 / H.265 を切り替えて比較する。
- HWA の有効・無効を選択できるコーデックは両方計測する (H.264 / H.265 は HWA のみ)。
- 端末は給電せず単独動作とし、Wi-Fi 環境で 30 分配信して計測する。
- 計測は端末再起動後に行い、室温と湿度をできるだけ合わせる。
- 画面輝度を 50 % にして自動調整を無効化し、縦画面で配信する。
- 解像度・コーデック・ビットレートを揃えた条件で比較する。
- 計測にはサーモグラフィーデバイスを使い、結果を記録する。

## 完了条件

- コーデックと HWA の有無ごとに端末温度の実測値が記録されている。
- 発熱の観点で推奨できる設定と避けるべき設定が説明できている。
- 必要なら SDK 側の対応 (設定の推奨、ドキュメント記載) が別 issue として起票されている。

## pending にした理由

2026-09-11 に pending にする。

- 実機とサーモグラフィーデバイスを使った計測が必要で、コード変更だけでは進められない。
- 計測条件を揃えて再現するのに手間がかかるため、まとまった計測時間を確保できるまで保留とする。
- 計測結果が出るまでは SDK 側で何を変えるかを決められない。
